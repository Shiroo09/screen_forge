# ScreenForge → Rust port roadmap

Goal: port the whole C#/WPF app to Rust, all features working, to bring memory
down. Source: 174 `.cs` (36,414 lines) + 11 `.xaml` across `ScreenForge/` and
`ScreenForge.WindowsAI/`.

## Why (measured, not assumed)

The shipping app idles at **118 MB working set / 516 MB private / 2.37 GB
virtual** (`Get-Process ScreenForge`). A tray app should not carry that.

The real peaks, however, are not framework overhead — they are in the C# code
and would follow a naive port:

| Where | Evidence | Peak |
|---|---|---|
| Export opens **every frame** as full BGRA at once | `GifEditorWindow.Panels.cs:1059` `slice.Select(f => f.Pixels).ToList()` | 2.5–7.5 GB for 10 s @ 30 fps 1080p |
| `Scene._undo` has **no limit**; `ImageItem.Clone` deep-copies the bitmap | `Editor/Scene.cs:72`, `Editor/StepBlurImageItems.cs:310` | unbounded |
| Undo snapshots pin the decoded-frame cache | `Gif/Editing/EditorDocument.cs:35,97,140` | 400 MB+ |
| Undisposed `SKBitmap` / `static ImageCache` | `Editor/Scene.cs:14`, `Gif/Editing/OverlayRenderer.cs:253` | leak per item |

Capture itself is fine (frames are Deflate-compressed in `FrameStore`,
~90 MB for the example above). The blow-up is **editor/export**. Rust must fix
the algorithm, not just the language: `GifFile<W: Write>` already streams.

## Port order (pure logic first — verifiable without the UI)

1. ✅ **`sf-gif`** — `Gif/Encoder/*`, `Gif/FrameStore.cs`. Byte-identical to C#.
2. ✅ **`sf-settings`** — `Settings/AppSettings.cs` + helpers. JSON-compatible.
3. **`sf-media`** — `Record/AudioConvert.cs`, `Record/VideoGeometry.cs`,
   `Record/VideoBitrate.cs`, `Gif/Editing/FrameOperations.cs` (pure math).
4. **`sf-net`** — `Upload/LitterboxUploadProvider.cs`, `Translate/*`
   (`ProtoWriter`, `ProtoResponseParser`, `GoogleLensClient`,
   `GoogleTextTranslateClient`, `TranslateLanguageRouter`),
   `Search/ReverseImageSearch.cs`. `reqwest` + `serde_json`; ProtoWriter is a
   ~50-line hand-rolled protobuf encoder, port it as-is.
5. 🟡 **`sf-capture`** — input layer + real GDI BitBlt screen capture done (`capture_virtual_screen`, `capture_region`, crop). Low-level input hooks still pending; DXGI duplication is the fast path to add.
6. 🟡 **`sf-edit`** — frame/document model, frame+image ops, edit history, view transform done; Skia scene graph/renderer still pending. Undo bounding addressed in the frame model.
7. **`sf-record`** — `Record/VideoRecorder.cs`, `MfH264Writer.cs`,
   `SystemLoopback.cs`, `AudioMixer.cs`. Hardest pure-Win32 piece:
   `windows-rs` IMF* + IAudioClient, no ready-made crate.
8. **`sf-app`** (UI) — `Windows/*.xaml(.cs)`, `Resources/*.xaml`. Rewrite, not
   port. egui/slint/iced/Tauri. `CaptureOverlayWindow` (4,470 lines) and
   `GifEditorWindow*` (4,460 lines) keep logic and UI in the same class — split
   before porting.

## Blockers with no Rust counterpart

| Blocker | C# source | Options |
|---|---|---|
| Windows App SDK AI (`ImageObjectExtractor`) | `ScreenForge.WindowsAI/SubjectSegmenter.cs` | No Rust binding. Make the `u2netp.onnx` path (`LocalSubjectSegmenter.cs`) the only path — it works via the `ort` crate. |
| Velopack auto-update | `Updates/AutoUpdateService.cs`, `App.xaml.cs:28` | No Rust equivalent. Rebuild download→apply→restart, or adopt a Tauri-style updater. |
| WPF UI (8 windows + 2 themes, ~16.8k lines) | `Windows/`, `Resources/` | Full redesign in a Rust UI toolkit. |
| Media Foundation + WASAPI | `Record/MfH264Writer.cs`, `SystemLoopback.cs` | `windows-rs` COM by hand. |
| WebView2 visual translate | `Translate/GoogleTranslateVisualClient.cs` | `wry` / `webview2-com`. |
| Explorer shell menu | `Background/ShellBackgroundMenu.cs` | `winreg` — easy. |

## Verification discipline

Each pure-logic crate ships with golden fixtures generated by the **real C#**
(`ScreenForge.Tests/Golden*Fixture.cs`, `SF_WRITE_GOLDEN=1`), so "matches the
original" is proven, not claimed. UI/OS crates need hardware-level comparison
instead (capture a frame both ways, diff).

## What runs now (verified on this machine)

```
screenforge png out.png          capture -> PNG
screenforge crop out.png 0 0 400 300
screenforge gif out.gif 10 100   N captures -> GIF
screenforge record out.gif 5 10  5 s real-time recording -> GIF
screenforge shot out.png         capture + clipboard (CF_DIB)
screenforge run                  tray shell, Alt+Shift+S captures (hotkey proven
                                 by driving Ctrl+Shift+F9 and getting 2 PNGs)
screenforge settings             reads %APPDATA%\ScreenForge\settings.json
```

Done since: MP4 (Media Foundation H.264) + WASAPI audio, interactive annotate
editor (rect/ellipse/arrow/line/pen/step/blur/text), system tray icon, live
upload client, settings-driven startup.

Still missing for full parity: the settings *window*, GIF editor timeline UI,
translate overlay wiring, and the two no-Rust-counterpart pieces (Windows App
SDK AI, Velopack).

The C# app has 369 xunit tests (`ScreenForge.Tests/`) that encode behaviour the
Rust crates must satisfy — treat them as the acceptance suite, porting the
relevant ones alongside each crate.
